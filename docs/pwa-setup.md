# PWA (Progressive Web App) Setup

InsightHub is configured as a Progressive Web App (PWA), allowing users to install it on their devices and use it offline.

## Features

- **Installable**: Users can install the app on their home screen (mobile and desktop)
- **Offline Support**: Cached assets work offline with service worker
- **Update Notifications**: Users are notified when new versions are available
- **Fast Loading**: Assets are cached for faster subsequent loads
- **App-like Experience**: Standalone display mode for native app feel

## Configuration

### Manifest

The app manifest (`public/manifest.json`) defines:
- App name and description
- Icons for various sizes
- Theme colors
- Display mode (standalone)
- Shortcuts (Dashboard, Settings)

### Service Worker

The service worker is automatically generated by `vite-plugin-pwa` using Workbox. It provides:
- **Static Assets Caching**: JS, CSS, HTML, images cached for offline use
- **API Caching**: Network-first strategy for API calls (5-minute cache)
- **Font Caching**: Google Fonts and MDI fonts cached for 1 year
- **Auth Handling**: Network-only for authentication endpoints

### Icons

The app uses multiple icon sizes for different platforms:
- `16x16`, `32x32`, `48x48`, `64x64`, `128x128`, `256x256`, `512x512` (standard)
- `180x180` (Apple touch icon)
- All icons are located in `client/public/`

## Development

### Testing PWA Features

1. **Build the app**:
   ```bash
   cd client
   npm run build
   ```

2. **Preview the build**:
   ```bash
   npm run preview
   ```

3. **Test in browser**:
   - Open DevTools → Application → Service Workers
   - Check "Offline" to test offline functionality
   - Open Application → Manifest to view manifest
   - Use "Add to Home Screen" to test installation

### Development Mode

PWA features are enabled in development mode (`devOptions.enabled: true`), so you can test:
- Service worker registration
- Update notifications
- Offline functionality

## Update Mechanism

When a new version is deployed:
1. Service worker detects the update
2. New service worker enters "waiting" state
3. `PWAUpdatePrompt` component shows update notification
4. User clicks "Update" to activate new version
5. Page reloads with new version

## Configuration Files

- `client/vite.config.js`: PWA plugin configuration
- `client/public/manifest.json`: Web app manifest
- `client/src/components/PWAUpdatePrompt.vue`: Update notification component
- `client/index.html`: PWA meta tags

## Customization

### Changing Theme Color

Update in both places:
1. `client/vite.config.js` → `manifest.theme_color`
2. `client/index.html` → `<meta name="theme-color">`

### Adding Icons

1. Add icon files to `client/public/`
2. Update `client/vite.config.js` → `manifest.icons`
3. Update `client/public/manifest.json` → `icons`

### Modifying Cache Strategy

Edit `client/vite.config.js` → `workbox.runtimeCaching` to change caching strategies for different URL patterns.

## Troubleshooting

### Service Worker Not Registering

1. Check browser console for errors
2. Ensure HTTPS (or localhost for development)
3. Clear browser cache and service workers
4. Check `vite.config.js` PWA configuration

### Updates Not Showing

1. Check if service worker is active in DevTools
2. Verify `PWAUpdatePrompt` component is mounted
3. Check browser console for service worker messages
4. Try hard refresh (Ctrl+Shift+R / Cmd+Shift+R)

### Offline Mode Not Working

1. Build the app first (`npm run build`)
2. Check service worker cache in DevTools
3. Verify assets are being cached
4. Check network tab for failed requests

## Production Deployment

1. Build the app: `npm run build`
2. Deploy the `dist/` folder
3. Ensure HTTPS is enabled (required for PWA)
4. Verify service worker is registered
5. Test installation on target devices
